# 食安智荐 · 运行与部署说明

基于多模态大模型思路设计的膳食营养分析与食谱推荐网页实践作品。当前版本为**离线演示版**：识别候选、营养估算与食谱生成均由内置知识库和规则引擎完成，无需配置 API 密钥，双击即可运行，适合课堂演示、源码检查与二次开发。

---

## 1. 目录结构

```
.
├── index.html              页面结构与四个功能模块
├── styles.css              样式（CSS 变量 + 流式响应式，无绝对定位）
├── data.js                 内置食物成分表、候选菜品库、食谱库、目标参数
├── app.js                  交互逻辑：食材解析、营养计算、识别、推荐、历史记录
├── prompts.md              四轮关键提示词模板（与实验报告补充材料对应）
├── AI交互记录.md           完整协作过程记录（可作为报告附件提交）
└── .github/workflows/deploy.yml   GitHub Pages 自动部署配置
```

## 2. 本地运行

方式一（最简单）：直接双击 `index.html`，在浏览器中打开。

方式二（推荐，避免个别浏览器的本地文件限制）：

```bash
cd 项目目录
python3 -m http.server 8000
```

然后访问 <http://localhost:8000/>。

无需安装依赖，无需构建步骤，无需后端服务。

## 3. 功能与操作

1. 上传菜品照片（可选），或直接输入食材，例如：`鸡胸肉 150g，西兰花 100g，糙米饭 1碗`。
2. 选择健康目标：减脂 / 增肌 / 均衡。
3. 勾选忌口与过敏原：不吃辣、素食、避免海鲜、花生过敏、乳糖不耐；也可自定义添加。
4. 点击「生成分析与食谱」，查看识别结果、营养四宫格和一日三餐。
5. 识别不准时点击「修改识别结果」直接纠正，系统按修正后的食材重算营养。
6. 点击「重新生成食谱」比较不同方案；点击「保存本次」把记录存入本机浏览器。

图片只在浏览器本地预览（`FileReader` 读取为 DataURL），**不会上传到任何服务器**。历史记录使用 `localStorage`，同样只存在本机。

## 4. 数据说明

- `data.js` 中的 `FOOD_DB` 为常见食物每 100g 可食部的营养参考值，用于离线估算。
- `parseIngredients()` 支持 `g / 克 / ml / 碗 / 个 / 根 / 片 / 勺 / 份` 等单位；未写份量时按该类食物的常见份量估算。
- 营养数值为估算结果，不等同于实验室检测值；混合菜品、复杂调味和实际烹饪用油都会带来偏差。

## 5. 如何接入真实大模型

演示版把模型相关能力集中在两个函数，替换为 API 调用即可，前端其余部分不用改：

| 函数 | 位置 | 当前实现 | 替换为 |
|------|------|----------|--------|
| `recognizeDish(textInput, file)` | `app.js` | 文件名关键词匹配 + 食材文本解析 | 多模态模型：图片 + 提示词 → JSON |
| `buildMealPlan(goal, restrictions, seed)` | `app.js` | 规则筛选 + 轮转选取 | 文本模型：用户画像 + 提示词 → JSON |

返回的 JSON 字段约定：

```json
// recognizeDish 返回
{ "name": "菜品名", "ingredients": ["鸡胸肉 150g", "西兰花 100g"], "confidence": "识别置信度：较高" }

// buildMealPlan 返回（数组，三项对应早/午/晚）
[{
  "type": "breakfast", "name": "食谱名", "ing": "食材清单",
  "kcal": 340, "protein": 14, "min": 8,
  "tags": ["乳制品"], "goal": "balance", "steps": ["步骤1", "步骤2"]
}]
```

提示词模板见 `prompts.md`。接入真实 API 时建议把密钥放在服务端代理中，不要写死在前端静态文件里。

## 6. 部署到 GitHub Pages

1. 在 GitHub 新建一个公开仓库，例如 `shian-zhijian`。
2. 把本目录所有文件上传到仓库根目录（包括 `.github` 文件夹）。
3. 进入仓库 **Settings → Pages**，Build and deployment 的 Source 选择 **GitHub Actions**。
4. 仓库内 `.github/workflows/deploy.yml` 会在每次 `push` 到 `main` 分支后自动构建并发布。
5. 等 Actions 显示绿色通过，访问 `https://<你的用户名>.github.io/<仓库名>/`。

若不想用 Actions，也可以手动发布：Settings → Pages → Source 选 **Deploy from a branch**，Branch 选 `main`、目录选 `/ (root)`，保存后等待部署完成。

> 注意：仅上传代码不等于完成部署。作业要求提交的是**能正常打开的 Pages 链接**，请务必在浏览器（最好再用手机）实际访问确认。

## 7. 已知限制

- 未接入真实食物数据库，无法给出精确到克的医学级建议。
- 图片识别为演示逻辑：根据文件名关键词匹配候选菜品；若不匹配则给出候选并要求人工确认。
- 食谱库规模有限，重新生成是在候选池内切换，不会无限产出新内容。
- 无任何账号体系，历史记录仅存本机，换设备不会同步。
